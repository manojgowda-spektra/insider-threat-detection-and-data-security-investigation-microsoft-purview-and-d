# Challenge 03: Hunt the Generated Activity with Advanced Hunting

### Estimated Duration: 75 minutes

## Scenario

Zava Manufacturing needs evidence that the departing design engineer handled proprietary design files, staged them in an exfiltration-like folder, sent an outbound message with an attachment, and triggered a Defender for Endpoint alert during the lab. You will use Microsoft Defender XDR Advanced Hunting to find telemetry generated by your own actions from Challenge 2 instead of relying on seeded tenant history.

## Overview

In this challenge, you will run KQL queries in Microsoft Defender XDR Advanced Hunting. The queries use variables for the risky user UPN, lab VM, source path, staging path, and time window so they work in a fresh sandbox tenant. You will query `DeviceFileEvents`, `DeviceEvents`, `EmailEvents`, and the alert tables `AlertInfo` and `AlertEvidence`. You will also apply retry and polling guidance because Defender telemetry can take several minutes to appear after onboarding and activity generation.

Some Advanced Hunting columns can vary by table, tenant, workload, or export surface. Before running each table-specific query, you will check the schema pane and the query uses `column_ifexists()` for optional columns such as `AccountUpn`, `To`, `RecipientDomain`, `DeliveryAction`, and `LatestDeliveryAction`.

## Task 2: Poll for lab VM telemetry before running focused hunts

In this task, you will use broad polling queries to confirm that Defender XDR has ingested recent telemetry from the onboarded lab VM.

1. Before running the polling query, confirm the device tables actually respond. The schema pane is not proof on its own - it lists the full catalogue, so a table can appear there and still fail to resolve when queried. Run `DeviceFileEvents | count` and `DeviceEvents | count` first. If only one of the two responds, keep `union isfuzzy=true` in the query so the available table can still return results. If neither responds, read the note at the end of this task before continuing.

2. Run the following query after replacing the variable values in the first lines. The query creates safe account fields with `column_ifexists()` so it does not fail when one table lacks `AccountUpn` or another account column.

   ```kusto
   let RiskyUpn = tostring('REPLACE_WITH_YOUR_LAB_ADMIN_UPN');
   let LabDeviceName = tostring('REPLACE_WITH_DEVICE_NAME_OR_PREFIX');
   let HuntStartTime = ago(6h);
   let HuntEndTime = now();
   union isfuzzy=true withsource=TableName DeviceFileEvents, DeviceEvents
   | where Timestamp between (HuntStartTime .. HuntEndTime)
   | extend SafeInitiatingUpn = tostring(column_ifexists('InitiatingProcessAccountUpn', ''))
   | extend SafeAccountUpn = tostring(column_ifexists('AccountUpn', ''))
   | where isempty(LabDeviceName) or DeviceName startswith LabDeviceName or DeviceName contains LabDeviceName
   | where isempty(RiskyUpn) or SafeInitiatingUpn =~ RiskyUpn or SafeAccountUpn =~ RiskyUpn
   | summarize EventCount=count(), FirstSeen=min(Timestamp), LastSeen=max(Timestamp) by Table=TableName, DeviceName
   | order by LastSeen desc
   ```

3. If the query returns rows for your lab VM, copy the `DeviceName` value from the results and update `LabDeviceName` in your later queries to that exact value.

4. If the query returns no rows, wait 5 minutes and run the query again. Repeat this polling cycle up to three times.

5. If the query still returns no rows after three retries, verify these prerequisites before continuing:

   - The lab VM was onboarded to Microsoft Defender for Endpoint in Challenge 2.
   - The VM appears in **Assets** > **Devices** in the Defender portal.
   - You copied files from `C:\LabFiles\ZavaDesignFiles` to the staging folder after onboarding.
   - Your `HuntStartTime` covers the time when you generated the file activity.

6. Run this count query to understand which tables are currently populated for your time window.

   ```kusto
   let HuntStartTime = ago(6h);
   let HuntEndTime = now();
   union isfuzzy=true withsource=TableName DeviceFileEvents, DeviceEvents, EmailEvents, AlertInfo, AlertEvidence
   | where Timestamp between (HuntStartTime .. HuntEndTime)
   | summarize Rows=count(), LastSeen=max(Timestamp) by Table=TableName
   | order by Rows desc
   ```

> [!Tip]
> Advanced Hunting is designed for proactive investigation across Defender XDR data, but ingestion is not always immediate. Treat an empty result during the first few minutes as a reason to poll and verify prerequisites, not as proof that the activity did not happen.

> [!Important]
> There are two different failures here, and they mean opposite things.
>
> **A query that runs and returns no rows** is the ingestion delay described above. Keep polling.
>
> **A query that fails with `Semantic error ... Failed to resolve table or column expression named 'DeviceFileEvents'`** is not your mistake and is not something polling will fix. That error means the Microsoft Defender for Endpoint device tables do not exist in this tenant yet. Microsoft Learn documents that Defender for Endpoint tenant provisioning can take up to 24 hours after the service is first enabled, and the `Device*` tables only appear once it completes.
>
> To tell the two apart, run `AlertInfo | count`. If `AlertInfo` resolves and returns a count while `DeviceFileEvents` and `DeviceEvents` fail to resolve, Advanced Hunting itself is working and the device tables are simply not provisioned. The endpoint is not at fault: a correctly onboarded VM reports `OnboardingState = 1` with the Sense service running, and its `Microsoft-Windows-SENSE/Operational` log records a successful machine profile report, while the tenant still returns nothing.
>
> If you hit this, record it in `C:\LabFiles\Challenge3-HuntingNotes.txt` and tell your instructor. Tasks 3, 4 and 6 depend on these tables and cannot be completed until provisioning finishes. Task 5 (`EmailEvents`) and the Microsoft Purview work in Challenge 4 are unaffected.

## Task 3: Hunt design file activity in `DeviceFileEvents`

In this task, you will identify file creation, modification, copy, and staging evidence for the Zava design files generated in Challenge 2.

1. In the schema pane, expand `DeviceFileEvents` and verify that `Timestamp`, `DeviceName`, `ActionType`, `FileName`, and `FolderPath` are present. If optional fields such as `SHA1`, `SHA256`, `InitiatingProcessAccountUpn`, or `InitiatingProcessCommandLine` are missing, the query below still runs because it uses safe aliases.

2. Run the following focused `DeviceFileEvents` query. Replace the variable values first.

   ```kusto
   let RiskyUpn = tostring('REPLACE_WITH_YOUR_LAB_ADMIN_UPN');
   let LabDeviceName = tostring('REPLACE_WITH_DEVICE_NAME_OR_PREFIX');
   let SourcePathFragment = tostring(@'C:\LabFiles\ZavaDesignFiles');
   let StagingPathFragment = tostring(@'C:\ExfilStaging');
   let HuntStartTime = ago(6h);
   let HuntEndTime = now();
   let DesignFileNames = dynamic([
       'AeroFrame-Assembly-RevC.step',
       'ZV-9000-Cooling-Manifold.dwg',
       'Prototype-Test-Matrix.xlsx',
       'Supplier-Costed-BOM-Q4.xlsx',
       'Manufacturing-Tolerances.pdf'
   ]);
   DeviceFileEvents
   | where Timestamp between (HuntStartTime .. HuntEndTime)
   | extend SafeInitiatingUpn = tostring(column_ifexists('InitiatingProcessAccountUpn', ''))
   | extend SafeInitiatingAccount = tostring(column_ifexists('InitiatingProcessAccountName', ''))
   | extend SafeSHA1 = tostring(column_ifexists('SHA1', ''))
   | extend SafeSHA256 = tostring(column_ifexists('SHA256', ''))
   | extend SafeInitiatingProcessFileName = tostring(column_ifexists('InitiatingProcessFileName', ''))
   | extend SafeInitiatingProcessCommandLine = tostring(column_ifexists('InitiatingProcessCommandLine', ''))
   | where DeviceName =~ LabDeviceName or DeviceName startswith LabDeviceName or DeviceName contains LabDeviceName
   | where FileName in~ (DesignFileNames)
       or FolderPath has SourcePathFragment
       or FolderPath has StagingPathFragment
   | where isempty(RiskyUpn) or SafeInitiatingUpn =~ RiskyUpn or SafeInitiatingAccount has tostring(split(RiskyUpn, '@')[0])
   | project Timestamp, DeviceName, ActionType, FileName, FolderPath,
             SHA1=SafeSHA1, SHA256=SafeSHA256,
             InitiatingProcessAccountUpn=SafeInitiatingUpn,
             InitiatingProcessAccountName=SafeInitiatingAccount,
             InitiatingProcessFileName=SafeInitiatingProcessFileName,
             InitiatingProcessCommandLine=SafeInitiatingProcessCommandLine
   | order by Timestamp asc
   ```

3. Inspect the returned rows. Look for events that show the design files being created, modified, renamed, copied, or written under the staging path.

4. If your staging path was not `C:\ExfilStaging`, update `StagingPathFragment` and rerun the query.

5. If file names appear but hashes are empty, continue. File hash fields are not guaranteed to be populated for every file event.

6. If the focused query returns no rows, run this broader file-name query to remove the UPN and path filters temporarily.

   ```kusto

   let HuntEndTime = now();
   let DesignFileNames = dynamic([

       'ZV-9000-Cooling-Manifold.dwg',
       'Prototype-Test-Matrix.xlsx',
       'Supplier-Costed-BOM-Q4.xlsx',
       'Manufacturing-Tolerances.pdf'
   ]);
   DeviceFileEvents
   | where Timestamp between (HuntStartTime .. HuntEndTime)
   | extend SafeInitiatingUpn = tostring(column_ifexists('InitiatingProcessAccountUpn', ''))
   | extend SafeInitiatingProcessFileName = tostring(column_ifexists('InitiatingProcessFileName', ''))
   | where FileName in~ (DesignFileNames)
   | project Timestamp, DeviceName, ActionType, FileName, FolderPath,
             InitiatingProcessAccountUpn=SafeInitiatingUpn,
             InitiatingProcessFileName=SafeInitiatingProcessFileName
   | order by Timestamp desc
   ```

## Task 4: Hunt device and removable-media signals in `DeviceEvents`

In this task, you will query miscellaneous endpoint telemetry for evidence related to staging behavior, removable storage, or Defender Antivirus detections.

1. In the schema pane, expand `DeviceEvents` and verify that the table is available. Confirm `Timestamp`, `DeviceName`, `ActionType`, and `AdditionalFields`. Check whether optional fields such as `FileName`, `FolderPath`, `InitiatingProcessAccountUpn`, `AccountUpn`, and `InitiatingProcessFileName` exist in your tenant.

2. Run the following `DeviceEvents` query to search for staging path activity and storage-related action types. The query uses safe field aliases so missing optional columns do not break the query.

   ```kusto
   let RiskyUpn = tostring('REPLACE_WITH_YOUR_LAB_ADMIN_UPN');
   let LabDeviceName = tostring('REPLACE_WITH_DEVICE_NAME_OR_PREFIX');
   let StagingPathFragment = tostring(@'C:\ExfilStaging');
   let HuntStartTime = ago(6h);
   let HuntEndTime = now();
   DeviceEvents
   | where Timestamp between (HuntStartTime .. HuntEndTime)
   | extend SafeFileName = tostring(column_ifexists('FileName', ''))
   | extend SafeFolderPath = tostring(column_ifexists('FolderPath', ''))
   | extend SafeInitiatingUpn = tostring(column_ifexists('InitiatingProcessAccountUpn', ''))
   | extend SafeAccountUpn = tostring(column_ifexists('AccountUpn', ''))
   | extend SafeInitiatingProcessFileName = tostring(column_ifexists('InitiatingProcessFileName', ''))
   | extend SafeAdditionalFields = tostring(column_ifexists('AdditionalFields', ''))
   | where DeviceName =~ LabDeviceName or DeviceName startswith LabDeviceName or DeviceName contains LabDeviceName
   | where isempty(RiskyUpn) or SafeInitiatingUpn =~ RiskyUpn or SafeAccountUpn =~ RiskyUpn
   | where SafeFolderPath has StagingPathFragment
       or SafeFileName has_any ('EICAR', 'eicar')
       or ActionType has_any ('Usb', 'USB', 'Removable', 'Drive', 'Storage', 'Antivirus', 'Malware')
       or SafeAdditionalFields has_any ('Usb', 'USB', 'Removable', 'Drive', 'Storage', 'EICAR', 'Malware')
   | project Timestamp, DeviceName, ActionType,
             FileName=SafeFileName,
             FolderPath=SafeFolderPath,
             InitiatingProcessAccountUpn=SafeInitiatingUpn,
             AccountUpn=SafeAccountUpn,
             InitiatingProcessFileName=SafeInitiatingProcessFileName,
             AdditionalFields=SafeAdditionalFields
   | order by Timestamp asc
   ```

3. Review the `ActionType` values returned by your tenant. The exact values can vary by sensor and event type. Use the in-portal schema reference to inspect supported `ActionType` values if you need to refine the query.

4. If you used a removable drive or secondary volume in Challenge 2, rerun the query with `StagingPathFragment` set to that drive path.

5. If no removable-media rows appear, do not invent evidence. Record that device storage telemetry was not available in this session and rely on `DeviceFileEvents` for the file-staging evidence.

2. Run the following `EmailEvents` query. Replace `RiskyUpn`, and optionally replace `ExternalRecipientFragment` with the external recipient address or domain you used in Challenge 2.

   ```kusto

   let HuntEndTime = now();
   EmailEvents
   | where Timestamp between (HuntStartTime .. HuntEndTime)
   | extend SafeSenderMailFromAddress = tostring(column_ifexists('SenderMailFromAddress', ''))
   | extend SafeRecipientDomain = tostring(column_ifexists('RecipientDomain', ''))
   | extend SafeTo = tostring(column_ifexists('To', ''))
   | extend SafeDeliveryAction = tostring(column_ifexists('DeliveryAction', ''))
   | extend SafeDeliveryLocation = tostring(column_ifexists('DeliveryLocation', ''))

       or RecipientEmailAddress has ExternalRecipientFragment
       or SafeRecipientDomain has ExternalRecipientFragment
       or SafeTo has ExternalRecipientFragment

             SenderFromAddress,
             SenderMailFromAddress=SafeSenderMailFromAddress,
             RecipientEmailAddress,
             RecipientDomain=SafeRecipientDomain,
             To=SafeTo,
             Subject, EmailDirection, AttachmentCount,
             DeliveryAction=SafeDeliveryAction,
   ```

## Task 6: Hunt Defender for Endpoint alert evidence

In this task, you will confirm the EICAR-generated Defender for Endpoint alert using Advanced Hunting alert tables and the Defender portal.

1. In the schema pane, expand `AlertInfo` and `AlertEvidence`. Confirm that `AlertId` is present in both tables. Check which source, device, file, and account columns are available. The following queries use safe aliases for optional evidence columns such as `DeviceName`, `FileName`, and `AccountUpn`.

2. Run the following alert query to find recent Microsoft Defender for Endpoint alerts for your lab VM or risky user.

   ```kusto
   let RiskyUpn = tostring('REPLACE_WITH_YOUR_LAB_ADMIN_UPN');
   let LabDeviceName = tostring('REPLACE_WITH_DEVICE_NAME_OR_PREFIX');
   let HuntStartTime = ago(6h);
   let HuntEndTime = now();
   AlertInfo
   | where Timestamp between (HuntStartTime .. HuntEndTime)
   | extend SafeServiceSource = tostring(column_ifexists('ServiceSource', ''))
   | extend SafeDetectionSource = tostring(column_ifexists('DetectionSource', ''))
   | extend SafeCategory = tostring(column_ifexists('Category', ''))
   | where SafeServiceSource =~ 'Microsoft Defender for Endpoint'
       or SafeDetectionSource has_any ('Antivirus', 'EDR', 'Microsoft Defender for Endpoint')
   | join kind=leftouter (
       AlertEvidence
       | where Timestamp between (HuntStartTime .. HuntEndTime)
       | extend EvidenceDeviceName = tostring(column_ifexists('DeviceName', ''))
       | extend EvidenceEntityType = tostring(column_ifexists('EntityType', ''))
       | extend EvidenceFileName = tostring(column_ifexists('FileName', ''))
       | extend EvidenceAccountUpn = tostring(column_ifexists('AccountUpn', ''))
       | extend EvidenceServiceSource = tostring(column_ifexists('ServiceSource', ''))
       | extend EvidenceDetectionSource = tostring(column_ifexists('DetectionSource', ''))
       | where isempty(LabDeviceName)
           or EvidenceDeviceName =~ LabDeviceName
           or EvidenceDeviceName startswith LabDeviceName
           or EvidenceDeviceName contains LabDeviceName
           or EvidenceAccountUpn =~ RiskyUpn
       | project AlertId, EvidenceTimestamp=Timestamp, EvidenceDeviceName, EvidenceEntityType,
                 EvidenceFileName, EvidenceAccountUpn, EvidenceServiceSource, EvidenceDetectionSource
   ) on AlertId
   | where isempty(LabDeviceName)
       or EvidenceDeviceName =~ LabDeviceName
       or EvidenceDeviceName startswith LabDeviceName
       or EvidenceDeviceName contains LabDeviceName
       or isnotempty(EvidenceDeviceName)
   | project Timestamp, AlertId, Title, Severity,
             Category=SafeCategory,
             ServiceSource=SafeServiceSource,
             DetectionSource=SafeDetectionSource,
             EvidenceTimestamp, EvidenceDeviceName,
             EntityType=EvidenceEntityType,
             EvidenceFileName, EvidenceAccountUpn,
             EvidenceServiceSource, EvidenceDetectionSource
   | order by Timestamp desc
   ```

3. Look for an alert title or evidence file name related to the EICAR test file you generated in Challenge 2. The exact title and severity can differ between tenants.

4. If the query returns no alert rows, run this broader EICAR search. It avoids direct references to optional `AlertEvidence` columns by creating safe aliases before filtering and projecting.

   ```kusto
   let HuntStartTime = ago(24h);
   let HuntEndTime = now();
   AlertInfo
   | where Timestamp between (HuntStartTime .. HuntEndTime)
   | extend SafeServiceSource = tostring(column_ifexists('ServiceSource', ''))
   | extend SafeDetectionSource = tostring(column_ifexists('DetectionSource', ''))
   | join kind=leftouter (
       AlertEvidence
       | where Timestamp between (HuntStartTime .. HuntEndTime)
       | extend EvidenceDeviceName = tostring(column_ifexists('DeviceName', ''))
       | extend EvidenceEntityType = tostring(column_ifexists('EntityType', ''))
       | extend EvidenceFileName = tostring(column_ifexists('FileName', ''))
       | extend EvidenceAccountUpn = tostring(column_ifexists('AccountUpn', ''))
       | project AlertId, EvidenceDeviceName, EvidenceEntityType, EvidenceFileName, EvidenceAccountUpn
   ) on AlertId
   | where Title has_any ('EICAR', 'test', 'malware', 'virus')
       or EvidenceFileName has_any ('EICAR', 'eicar')
       or SafeDetectionSource has_any ('Antivirus', 'EDR')
       or SafeServiceSource =~ 'Microsoft Defender for Endpoint'
   | project Timestamp, AlertId, Title, Severity,
             ServiceSource=SafeServiceSource,
             DetectionSource=SafeDetectionSource,
             DeviceName=EvidenceDeviceName,
             EntityType=EvidenceEntityType,
             FileName=EvidenceFileName,
             AccountUpn=EvidenceAccountUpn
   | order by Timestamp desc
   ```
