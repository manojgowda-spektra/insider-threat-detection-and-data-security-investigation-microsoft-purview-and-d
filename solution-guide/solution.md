# Facilitator Solution Guide

## Assessment boundary

Use the five canonical validators below. Microsoft Purview portal-only configuration remains facilitator-inspected because it cannot be read reliably by the external validator. Validators fail closed and do not grade screenshots, answer text, transcripts, or attestations.

| Challenge | Canonical validator | Automated scope | Facilitator scope |
|---|---|---|---|
| 1 | `Validations/01-task-vm-readiness-and-lab-assets.ps1` | VM, Custom Script Extension, local assets, Python, and packages | Audit readiness, Purview role-group membership, HR connector, and Insider Risk policy |
| 2 | `Validations/02-task-defender-onboarding-telemetry-alert-and-alert-sharing.ps1` | Recent MDE device telemetry and lab-linked EICAR/test-file alert evidence | Purview-to-Defender XDR alert-sharing setting |
| 3 | `Validations/03-task-advanced-hunting-evidence.ps1` | Inspection of `C:\LabFiles\Challenge3-HuntingNotes.txt` | Query quality and portal telemetry review |
| 4 | `Validations/04-task-dsi-exported-evidence.ps1` | Real, non-empty, parseable DSI or eDiscovery export evidence under `C:\LabFiles\DSIExports\` | Case workflow, DSI availability, authorization, and cost decisions |
| 5 | `Validations/05-task-graph-export-artifacts-and-alert-content.ps1` | App-only Graph access and recent lab-linked MDE alert content in both outputs | Credential, app, DSI, and eDiscovery cleanup after validation |

Challenge 3 includes the inline tag `<validation step="03-task-advanced-hunting-evidence"/>`. The tag invokes the canonical Challenge 3 validator and must remain in the learner guide.

Do not require an Insider Risk Management alert or correlated Defender XDR incident. Insider Risk scoring can take 24 hours or longer. Challenge 5 reads Microsoft Defender for Endpoint alert evidence generated by the EICAR activity.

## Documentation verification notes

The terminology and API expectations in this guide were checked against the current Microsoft Learn documentation for:

- Microsoft Graph `GET /security/alerts_v2`, including the `SecurityAlert.Read.All` application permission, the response `value` collection, `@odata.nextLink`, and filtering on `createdDateTime`.
- Microsoft Purview **Settings** > **Roles and scopes** > **Role groups** and the **Insider Risk Management** role group.
- Microsoft Purview **Data Security Investigations**, including investigations, full draft mode, data sources, investigation settings, and investigation deletion. Portal labels can vary by tenant rollout.

## Azure baseline

Expected resources are `labvm-<DeploymentID>`, its network resources, a public DNS/FQDN, and a successful Custom Script Extension. No `Microsoft.DevTestLab/schedules` resource is deployed.

```powershell
Connect-AzAccount
$sub = (Get-AzContext).Subscription.Id
Set-AzContext -SubscriptionId $sub
$vm = Get-AzVM | Where-Object Name -Like 'labvm-*' | Select-Object -First 1
if (-not $vm) { throw 'Lab VM not found.' }
$rg = $vm.ResourceGroupName
$vmName = $vm.Name
$DID = $vmName -replace '^labvm-', ''

Get-AzVM -ResourceGroupName $rg -Name $vmName -Status |
    Select-Object Name,Location,PowerState
Get-AzVMExtension -ResourceGroupName $rg -VMName $vmName |
    Select-Object Name,ProvisioningState

$schedules = Get-AzResource -ResourceType Microsoft.DevTestLab/schedules `
    -ErrorAction SilentlyContinue | Where-Object ResourceGroupName -eq $rg
if ($schedules) { throw 'Unexpected DevTestLab schedule exists.' }
```

```bash
SUB_ID="$(az account show --query id -o tsv)"
az account set --subscription "$SUB_ID"
RG="$(az vm list --query "[?starts_with(name,'labvm-')].resourceGroup | [0]" -o tsv)"
VM_NAME="$(az vm list -g "$RG" --query "[?starts_with(name,'labvm-')].name | [0]" -o tsv)"
az vm get-instance-view -g "$RG" -n "$VM_NAME" \
  --query "{name:name,location:location,power:instanceView.statuses[?starts_with(code,'PowerState/')].displayStatus|[0]}"
az vm extension list -g "$RG" --vm-name "$VM_NAME" \
  --query "[].{name:name,state:provisioningState}" -o table
az resource list -g "$RG" --resource-type Microsoft.DevTestLab/schedules -o table
```

Treat a failed CSE as infrastructure failure. Inspect `C:\WindowsAzure\Logs\Plugins\Microsoft.Compute.CustomScriptExtension\` and `C:\WindowsAzure\Logs\CloudLabsCustomScriptExtension.txt`. Common causes are wrong subscription/resource group, incompatible resource locations, regional capacity, transient downloads, or storage/SKU throttling. The solution does not require a system-assigned managed identity for Microsoft 365 or Graph.

## Challenge 3 — Hunt generated activity

### Expected end state

The learner runs bounded Advanced Hunting queries against available tables, including `DeviceFileEvents`, `DeviceEvents`, `EmailEvents`, `EmailAttachmentInfo`, `AlertInfo`, and `AlertEvidence`. Queries use the exact VM, risky UPN, staged filenames, and lab time window.

`C:\LabFiles\Challenge3-HuntingNotes.txt` records concrete endpoint, alert, email, and file findings plus honest telemetry gaps. Challenge 3 includes `<validation step="03-task-advanced-hunting-evidence"/>`, which validates this artifact.

### Reference queries

```kusto
let Since = ago(6h);
let Device = "labvm-REPLACE_WITH_DID";
DeviceFileEvents
| where Timestamp >= Since
| where DeviceName startswith Device
| where FolderPath contains "ExfilStaging" or PreviousFolderPath contains "ZavaDesignFiles"
| project Timestamp, DeviceName, ActionType, FileName, FolderPath,
          PreviousFolderPath, InitiatingProcessAccountUpn
| order by Timestamp desc
```

```kusto
let Since = ago(6h);
let Device = "labvm-REPLACE_WITH_DID";
AlertInfo
| where Timestamp >= Since
| join kind=leftouter (
    AlertEvidence
    | where Timestamp >= Since
    | where DeviceName startswith Device or FileName contains "eicar"
    | project AlertId, DeviceName, FileName, FolderPath, SHA256, AccountUpn
  ) on AlertId
| where DeviceName startswith Device or Title contains "EICAR" or FileName contains "eicar"
| project Timestamp, AlertId, Title, ServiceSource, DetectionSource,
          DeviceName, FileName, FolderPath, SHA256, AccountUpn
```

```kusto
let Since = ago(6h);
let RiskyUPN = "replace@tenant.example";
EmailEvents
| where Timestamp >= Since and SenderFromAddress =~ RiskyUPN
| join kind=leftouter (
    EmailAttachmentInfo
    | where Timestamp >= Since
    | project NetworkMessageId, AttachmentFileName=FileName
  ) on NetworkMessageId
| project Timestamp, SenderFromAddress, RecipientEmailAddress, Subject,
          AttachmentFileName, NetworkMessageId
```

Confirm optional columns in the schema before querying. Use `column_ifexists()` when necessary.

### Task rubric

| Task | Full credit | Partial credit | Common pitfalls |
|---|---|---|---|
| Scope and retry | Exact VM/UPN/path, UTC-aware bounded window, and reasonable polling. | Wider but bounded window. | Example identifiers; local time treated as UTC; unbounded hunt. |
| File/device evidence | Staged filename/path appears on the exact VM; available device context is recorded. | Valid row lacks an optional field. | Requiring one action type; activity predates onboarding. |
| Email evidence | Risky sender correlates with attachment metadata when licensed. | Missing table/ingestion gap is documented. | Expecting attachment names in `EmailEvents` alone. |
| Alert evidence | Recent MDE/EICAR evidence is tied to the exact VM or test-file indicator. | Portal evidence exists while hunting ingestion is pending. | Selecting an old alert or IRM source. |
| Notes artifact | Notes identify VM, path/file, tables, time window, and findings/gaps. | One unavailable source is clearly identified. | Screenshot only; generic prose; missing device/table/evidence terms. |

## Challenge 4 — Export DSI or eDiscovery evidence

### Cost-safe default and expected end state

The default is the lowest-export, cost-safe route:

1. Use DSI only when available, authorized, and explicitly cost-approved.
2. Scope one risky user and the shortest useful date range.
3. Select the smallest positive result set.
4. Prefer an eDiscovery **items report only** export when it supplies sufficient Zava metadata.
5. Export source items or use DSI storage/AI analysis only when the instructor approves the additional need and cost.

Expected outcome:

- **Insider Threat Case - Design Engineer** exists as a DSI investigation when approved, or as an eDiscovery case on the fallback route.
- Search scope uses the exact risky UPN, bounded dates, Zava names, and outbound message/attachment evidence.
- A real, non-empty portal export is saved recursively under `C:\LabFiles\DSIExports\`.
- `dsi_case_evidence.json` is generated from the real export and is not handwritten evidence.
- After Challenges 4 and 5 validate, disposable DSI/eDiscovery data, exports, and any metered investigation are deleted unless retention is required.

### Task rubric

| Task | Full credit | Partial credit | Common pitfalls |
|---|---|---|---|
| Confirm route | DSI is used only with availability, authorization, and cost approval; otherwise eDiscovery is selected. | Correct route is awaiting provisioning. | Enabling metered DSI without approval. |
| Create investigation/case | Exact name is used in an approved DSI investigation or eDiscovery case. | Provisioning is visibly pending. | Treating a local note as a case. |
| Add data source | Exact risky UPN and available mailbox/site sources use bounded dates. | Exchange-only while other sources provision. | Tenant-wide scope; simulated colleagues; endpoint-only files assumed searchable. |
| Search/refine | Supported filename, keyword, participant, and date criteria return controlled evidence. | Search is indexing; no export credit yet. | Overconstrained `AND`; local paths used as cloud properties. |
| Label exploration | Existing label filters are tested without creating a dependency on new labels. | Filter is unavailable and documented. | Creating/publishing a label and waiting for propagation. |
| Export | Smallest useful positive report/result is exported; source items only with approval. | None for automated credit until genuine evidence exists. | Zero-result export; screenshot; fabricated JSON; unnecessarily broad source-item export. |
| Normalize | JSON derives from the export and identifies case/search, UPN, positive count, terms, and files. | Minor optional field absent while source remains valid. | Typed narrative as evidence; deleting source export too early. |
| Cleanup | After Challenge 5 and validation, disposable DSI investigation/case/export data is removed unless retained by instruction. | Cleanup is scheduled with the tenant owner. | Leaving metered DSI storage/AI capacity running. |

### Verification

```powershell
$script = @'
$root = 'C:\LabFiles\DSIExports'
if (-not (Test-Path $root)) { throw 'DSIExports is missing.' }
$files = @(Get-ChildItem $root -Recurse -File)

Invoke-AzVMRunCommand -ResourceGroupName $rg -VMName $vmName `
  -CommandId RunPowerShellScript -ScriptString $script
```

The validator requires real, non-empty, parseable DSI/eDiscovery evidence that identifies the case/search and risky user, contains Zava filename or outbound-message evidence, and reports a positive item/result count. Missing, empty, malformed, zero-result, and fabricated artifacts fail.

### Required cleanup

Retain `C:\LabFiles\DSIExports\` through Challenge 5 and all validation. Then, unless retention is required:

- In DSI, open **Data Security Investigations** > **Investigations**, open the lab investigation, then use **Investigation settings** > **Actions** > **Delete investigations**. Confirm the destructive action with the instructor because deleted investigations cannot be recovered.
- Remove the disposable eDiscovery case/search/export according to tenant retention requirements.
- Coordinate with the tenant owner before removing any DSI compute/capacity resource.
- Delete local exports only after the Challenge 5 inventory and validation are complete.

## Challenge 5 — Export recent MDE evidence through Microsoft Graph

### Expected end state

- `C:\LabFiles\config.json` contains real `tenant_id`, `client_id`, and `client_secret` values for the disposable Graph app.
- The app has Microsoft Graph application permission `SecurityAlert.Read.All` with admin consent.
- The prepared script acquires an app-only token with `https://graph.microsoft.com/.default`.
- The authentication-only command is `--smoke-test`.
- The explicit device selector is `--vm-name`; the starter does not define `--auth-test`, `--device-name`, or `--indicator`.
- The script calls `https://graph.microsoft.com/v1.0/security/alerts_v2`, uses a server-side `createdDateTime ge` filter, reads `value`, and follows `@odata.nextLink`.
- Client-side selection retains recent MDE alerts linked to the VM name or recognizable EICAR/test-file evidence.
- `insider_risk_case.json` and `insider_risk_case_report.txt` contain genuine alert data and imported Challenge 3/4 evidence.

The current script source of truth writes these top-level JSON fields:

- `generatedUtc`
- `cutoffUtc`
- `labVmName`
- `recentAlertCount`
- `labScopedMdeAlertCount`
- `labScopedMdeAlertSummaries`
- `labScopedMdeAlerts`
- `challenge3HuntingNotes`
- `dsiCaseEvidenceParsed`
- `dsiExportInventory`

Each item in `labScopedMdeAlertSummaries` can contain `id`, `title`, `severity`, `status`, `serviceSource`, `detectionSource`, `createdDateTime`, `lastUpdateDateTime`, `alertWebUrl`, and `evidenceCount`. Full Graph objects, including evidence when returned, are retained under `labScopedMdeAlerts`.

### Task rubric

| Task | Full credit | Partial credit | Common pitfalls |
|---|---|---|---|
| Inspect config | Required local keys exist without disclosing the secret. | Config absent and learner correctly uses fallback. | Printing or publishing credentials. |
| Smoke test | `python .\get_insider_alerts.py --smoke-test` prints token-acquisition success and exits 0. | Correct permission is still propagating. | Using nonexistent `--auth-test`; stale secret; no consent. |
| Prepare app | Application `SecurityAlert.Read.All` has admin consent; secret value is stored only locally. | Correct permission awaits propagation. | Delegated permission; secret ID instead of value; wrong tenant. |
| Inspect script | Starter is preserved and current argument/schema names are recognized. | A small configuration repair is required. | Replacing the starter; following obsolete command examples. |
| Retrieve pages | Request uses `createdDateTime ge`, reads `value`, and follows `@odata.nextLink`. | One page is valid when no next link exists. | Legacy endpoint; no pagination; using update time for recency. |
| Select alert | MDE source plus exact VM or EICAR/test-file linkage is present. | Matching portal alert is still propagating to Graph. | Unrelated recent alert; assuming IRM alerts are required. |
| Preserve evidence | Full alert is in `labScopedMdeAlerts`; a faithful summary is in `labScopedMdeAlertSummaries`. | Optional Graph fields are absent from the source response. | Expecting fabricated UPN/hash fields; dropping linkage evidence. |
| Incorporate Challenge 3 | `challenge3HuntingNotes` identifies the path, existence, content, and length when available. | One source is unavailable and honestly represented. | Looking for obsolete `analystNotes`. |
| Inventory Challenge 4 | `dsiCaseEvidenceParsed` and recursive `dsiExportInventory.files` reflect real files. | Minor report formatting issue while JSON inventory is complete. | Looking for obsolete `dsiExportFiles`; top-level-only enumeration. |
| Write outputs | JSON parses, count is positive, and report repeats real alert and investigation evidence. | Cosmetic report defect only. | Looking for obsolete `alerts`, `alertSummaries`, `caseName`, or `queryMetadata`. |

### Verification commands matching the starter

```powershell
Invoke-AzVMRunCommand -ResourceGroupName $rg -VMName $vmName `
  -CommandId RunPowerShellScript -ScriptString @'
Set-Location C:\LabFiles

python .\get_insider_alerts.py --smoke-test
if ($LASTEXITCODE -ne 0) { throw 'Graph authentication smoke test failed.' }

python .\get_insider_alerts.py --vm-name $env:COMPUTERNAME
if ($LASTEXITCODE -ne 0) { throw 'Graph export failed or no lab-scoped MDE alert matched.' }

$case = Get-Content .\insider_risk_case.json -Raw | ConvertFrom-Json
$case | Select-Object generatedUtc,cutoffUtc,labVmName,recentAlertCount,labScopedMdeAlertCount

$alerts = @($case.labScopedMdeAlerts)
$summaries = @($case.labScopedMdeAlertSummaries)
if ($case.labScopedMdeAlertCount -lt 1 -or $alerts.Count -lt 1 -or $summaries.Count -lt 1) {
  throw 'No lab-scoped MDE alerts were exported.'
}
if ($case.labScopedMdeAlertCount -ne $alerts.Count) {
  throw 'labScopedMdeAlertCount does not match labScopedMdeAlerts.'
}

$cutoff = [datetimeoffset]::Parse($case.cutoffUtc)
$expected = $env:COMPUTERNAME
$results = foreach ($a in $alerts) {
  $raw = $a | ConvertTo-Json -Depth 50 -Compress
  $created = [datetimeoffset]::Parse($a.createdDateTime)
  [pscustomobject]@{
    Id = $a.id
    CreatedUtc = $created.UtcDateTime
    Recent = ($created -ge $cutoff)
    MDE = ($a.serviceSource -eq 'microsoftDefenderForEndpoint' -or
           $a.detectionSource -eq 'microsoftDefenderForEndpoint' -or
           $raw -match '(?i)microsoft\s*defender\s*(for\s*)?endpoint')
    LabLinked = ($raw -match [regex]::Escape($expected) -or
                 $raw -match '(?i)eicar|standard-antivirus-test-file|antivirus test|test file')
  }
}
$results | Format-Table
if (-not ($results | Where-Object { $_.Recent -and $_.MDE -and $_.LabLinked })) {
  throw 'No alert satisfies cutoff, MDE source, and lab linkage.'
}

$case.labScopedMdeAlertSummaries |
  Select-Object id,title,severity,status,serviceSource,detectionSource,createdDateTime,lastUpdateDateTime,evidenceCount,alertWebUrl |
  Format-Table -AutoSize

if (-not $case.challenge3HuntingNotes.path) { throw 'Challenge 3 notes metadata is absent.' }
if (-not $case.dsiCaseEvidenceParsed.path) { throw 'Normalized DSI/eDiscovery metadata is absent.' }
$inventory = @($case.dsiExportInventory.files)
if ($inventory.Count -eq 0) { throw 'Recursive DSI/eDiscovery inventory is empty.' }
$inventory | Select-Object relativePath,fullPath,sizeBytes,modifiedUtc,sha256 | Format-Table -AutoSize

if (-not (Test-Path .\insider_risk_case_report.txt)) { throw 'Text report is missing.' }
Select-String .\insider_risk_case_report.txt `
  -Pattern 'Server-side Graph cutoff','Recent lab-scoped MDE alerts matched','Challenge 3 hunting notes','DSI/eDiscovery export inventory'
'@
```

Expected smoke-test output:

```text
Token acquisition succeeded. Graph app configuration is usable for client credentials.
```

Expected successful export console pattern:

```text
Retrieved N recent alerts_v2 objects using createdDateTime ge TIMESTAMP.
Matched M recent lab-scoped Microsoft Defender for Endpoint alert(s).
Wrote C:\LabFiles\insider_risk_case.json

```

Do not use unsupported `--auth-test`, `--device-name`, or `--indicator` switches.

## Cross-cutting pitfalls

- **Wrong region/resource group:** verify the active subscription and keep VM networking resources in compatible locations.
- **Missing identity:** do not assume a system-assigned identity; no Purview managed-identity validator belongs in this package.
- **Permission boundaries:** Azure RBAC, Purview role groups, Defender permissions, Graph application permissions, and admin consent are independent and propagate separately.
- **Soft deletion:** recoverable applications, Key Vault objects, or Azure resources can block or confuse re-creation.
- **Throttling/capacity:** avoid repeated extension deployments during regional capacity or storage/SKU throttling. If Graph throttles the supplied starter, wait for the service-directed interval and rerun; do not treat HTTP success alone as evidence.
- **DSI cost:** use the report-only/smallest-positive-export default, obtain approval before metered DSI use, and delete disposable investigation data after validation.
- **Telemetry latency:** retry bounded searches while retaining strict time/device/evidence filters.
- **No DevTestLab schedule:** any `Microsoft.DevTestLab/schedules` resource is a package defect.
